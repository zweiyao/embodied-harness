# Qwen API 速度诊断与可选 Mac 出口

## 结论

小文本直连调用低于一秒；多模态大请求的远程上传耗时和波动明显。代理会进一步放大问题，但已完成的空经验实验本身配置了该域名直连，因此不能把历史慢调用全部归因于代理。

本轮找到可复现的提速路径：远程通过 SSH 加密通道将完整请求交给 Mac，再由 Mac 直连原阿里云北京入口。没有裁剪图像、改提示词、更换模型、降低输出预算或执行返回的动作。

## 实测

短请求均要求仅回复 OK，关闭思考，输出上限 32 token，各路径三次，全部 HTTP 200：

| 发起位置/路径 | 完整耗时范围 |
| --- | --- |
| 远程直连 | 0.65–0.80 秒 |
| 远程既有代理 | 1.20–1.47 秒 |
| Mac 直连 | 0.54–0.64 秒 |
| Mac 既有代理 | 0.54–0.59 秒 |

这些短请求不能代表任务调用。由已安装 provider 配合 mock transport 重建的三份历史请求分别为 17.8 KB、1.83 MB、4.66 MB；包含 17 个工具、0/3/6 张图像。模型输入 token 数分别为 4670、10745、23067，与历史对应请求一致。原始图片字节从归档中恢复，未重新缩放或压缩。真实请求保持原 16384 输出上限与 enable_thinking=false。

1.83 MB 请求：远程代理 47.76 秒，远程直连 7.07 秒，Mac 两条路径 3.84/3.96 秒。4.66 MB 请求：远程代理 90 秒未返回而被诊断程序终止。以上为各单次诊断，缓存与输出长度不同，不能直接解释为纯网络倍率。

对 4.66 MB 请求进一步进行三组交替比较，全部输入 token 为 23067，缓存命中均为 23040；请求文件 SHA256 相同：

| 远程使用的出口 | 次数 | 完整耗时中位数 | 首个文本/工具增量中位数 | 完整耗时范围 |
| --- | ---: | ---: | ---: | ---: |
| 远程直接访问阿里云 | 3 | 23.31 秒 | 21.54 秒 | 14.83–28.20 秒 |
| SSH → Mac → 同一阿里云入口 | 3 | 6.04 秒 | 3.46 秒 | 5.37–7.26 秒 |

本次完整耗时中位数减少约 74%。输出 token 数仍有随机差异，不能据此保证后续所有调用都提速同一比例。首个增量下降也明显，支持收益主要位于响应生成前的路径。该组 Mac relay 复用了上游连接；后续每次新建上游连接的候选版本三次均成功，耗时 5.01、8.43、9.19 秒，中位 8.43 秒。这组是后续验证，没有重新交替直连组，不能声称同样的精确提速比例；见 remote-mac-relay-fresh.json。

已用运行环境现有 build_api_model 构造的 provider client 通过 Mac 出口调用同一大请求：关闭自动重试，成功，首个增量 2.06 秒、完整 7.32 秒。只验证 SDK/网络兼容，没有运行任务控制循环。

## 为什么会慢

1. **不是只有一段提示词。** 旧实验带有累计多模态历史，原版 Qwen 每次请求仅图像的 base64 数据中位约 4.90 MB、最大约 40.46 MB。空经验组也有中位约 3.15 MB、最大约 16.73 MB。这里按归档二进制长度估算，不包含工具声明、文本及 JSON 结构。
2. **上传阶段已直接观测到瓶颈。** 同一 4.66 MB 请求，远程 HTTPX 发送请求体约 9.53 秒，发送结束到响应头约 2.46 秒。HTTPX2 的多次记录中，发送请求体约 6–28 秒，发送结束到响应头约 2 秒。传输追踪中的 send 完成是客户端交付请求体的阶段边界，不是服务端接收完毕的精确时刻；后半段仍含传输尾部、排队及推理。
3. **连接复用不是充分修复。** SDK 默认空闲连接保留 5 秒。改成 60 秒后确实跨过 7 秒间隔复用了连接，但该次发送仍用了约 27.87 秒。没有据此修改 SDK 或生产配置。
4. **历史数据不支持只怪生成长答案。** 原版/空经验输出 token 中位约 104/124.5；输出量与等待时间的线性相关接近零。输入长度有一定相关，但不能用相关性分离网络、缓存和排队因素。

Mac relay 的请求体从远程经 SSH 到 Mac 约 1.7–1.9 秒；复用上游连接的记录中，Mac 发送阶段约 0.09–0.35 秒。国内模型服务地址近，不代表每台机器的上传路径、吞吐和代理链路相同。

## 已排除的快捷方案与限制

- 当前代码和历史请求均已关闭思考，流式输出也已开启；无需重复加入这些“优化”。[阿里云思考模式文档](https://help.aliyun.com/zh/model-studio/deep-thinking)说明了 enable_thinking 参数，但本项目是否关闭以实际请求为准。
- gzip 请求体试验返回 400 invalid_parameter_error，该端点本次没有接受此编码；未部署。
- HTTP/2 的 HTTPX 比较因缺少可选 h2 依赖未运行；未安装或修改运行环境依赖。
- 第一次 SDK 回放把厂商扩展字段作为 SDK 顶层参数，产生本地 TypeError，尚未发出请求；改放 extra_body 后兼容验证成功，错误摘要保留。
- 代理 90 秒诊断超时保留在记录中，不把它归入机器人实验结果。
- 没有采集足以断言具体 ISP 限速、丢包位置或服务端队列状态的证据。确认的是传输阶段耗时、路径差异与小样本替代出口收益。

## 本轮边界与后续

所有返回的工具调用都丢弃，环境动作数为零。凭据仅在进程内通过现有 key_file 读取或经 SSH 获取，没有写入新凭据文件；日志只包含时间、计数和用量。完整历史请求和原始图片不提交 Git。

临时 Mac relay 与 SSH 隧道结束后关闭；原工作台配置、经验、提示词、工具和 harness 源码未修改。清理结果见 cleanup.json。

建议先接入一个独立、可选的 Mac 出口模型配置并做稳定性检查，见 [准确改动草案](proposal.md)。它依赖 Mac 在线，不能保证无人值守期间可用；不应静默切换出口污染后续实验的网络条件。大批量任务实验尚未开始。
