任务 4 两次 sensor_patch_batch 参数都违反实际声明：先把整数像素传给归一化坐标接口，收到明确重试反馈后又提交带字符串的三元素点。工具实现没有被调用，7 次已 dispatch 的其他工具调用与这两个被 SDK 拒绝的尝试分开计数。它属于有效模型失败；原 outcome/error、最初 incident 和分类前结果均保留，追加 [分类修正](classification-corrections.json)，没有重跑或提高重试额度。狭义证据分类器的 10 项检查通过，不能把所有 UnexpectedModelBehavior 一概改为模型失败。

任务 0 先尝试学习式拾取，未抓起物体，随后手动恢复。M 六次实际执行并正常返回；五次达到原伺服容差，一次下降达到 80 步仍略有残差。旧旋转动作伴随明显位置变化和碰撞，之后空抓抬升，最终再次闭爪后请求耗尽。未建立持物搬运，也没有 release。因此本轮验证了采用和接近/恢复运动，未验证持物搬运收益。模型还接受了桌面/低侧壁的假篮口测量，但没有搬向该位置，不能把它写成已执行的错误放置。详见 [轨迹诊断](diagnosis.md)。

两任务初始双相机图像与 C、03 逐字节相同，实际 API 声明均为 17 个 function tools 加 finish，4944 项保护哈希通过。两个 owned 工作台已停止，主工作台 server/config/network 保持。运行审计覆盖为 **partial**：未保存当时环境子进程的命令和环境变量快照；事后仍存活的工作台进程核验了隔离来源和六代理为空，环境子进程入口/无 EEF 包装只由冻结配置、预检及日志支持。该缺失不允许重造同期证据，也不作为剔除有效失败的理由。下一运行器将在环境进程出现时自动持久化有限、无凭据的快照。
