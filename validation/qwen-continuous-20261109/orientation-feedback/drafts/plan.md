The falsifiable expectations are corrected controller command magnitudes/basis, feedback toward the retained starting position after deviation, and lower measured position/orientation error in bounded rotation probes. ## Smallest interface and exact behavior

Proposed new source `robots/libero/research/orientation.py` is fully drafted in `orientation.py.draft`. No additions to `eef_control.py` or `LiberoPrimitives`; their versions and behavior stay byte-identical.

`rotate_axis(axis, angle_rad)` exposes exactly two required fields: axis is `x` or `z` in world coordinates; angle is finite signed radians in [-pi, pi], following the right-hand rule. It is a relative axis-angle rotation, not an Euler pitch/yaw coordinate assignment. Booleans, other axes and nonfinite/out-of-range angles are invalid. This new bounded angle contract intentionally does not support multi-turn requests; report it as a capability difference.

The call freezes current grip-site XYZ and observed EEF-body orientation. It left-multiplies one requested global rotation to obtain a single frozen target. It calls unchanged `EefControl.move_eef(target_xyz, target_quat, gripper=0, steps=10)` at most four times. Each native step uses the actual installed controller scale and base orientation through the existing robot-only getter. The outer loop stops at chunk boundaries if both residuals meet the existing native defaults: position tolerance from `move_to` (currently 0.012 m), full angular-distance tolerance from `rotate_wrist` (currently 0.02 rad). Angular tolerance now applies to a full orientation residual rather than a projected Euler-like scalar; this is an explicit interface change. Pose already at the target causes zero actions. Cancellation remains checked by native stepping, termination/truncation prevents further chunks. There is no hidden retry, waypoint, grasp, lowering or release.

At most 40 actual action steps are reported, not arrival-check iterations. The result includes frozen target, measured final robot state, both residuals/tolerances, action count, retained gripper command and episode flags. `target_reached` means pose tolerance only. Existing `_execute_primitive` supplies the normal post-action observations/images and recording once for this tool. Internal chunk results are not model requests; all action frames remain in native recording. A 10-step chunk continues until its own budget even if tolerance is crossed mid-chunk, as existing `move_eef` does; it introduces no extra mid-chunk controller or cancellation logic.

This feedback is not a collision-avoidance or grasp controller. Starting XYZ is a feedback target, not an exact guaranteed trajectory constraint. Large requested rotations can fail to converge or collide, including while pursuing the retained position. A failure at the finite limit is reported, not automatically retried. The draft does not supply object pose, contact readiness, pad offsets or full gripper geometry.

## Body/site convention proof and remaining runtime gate

Installed `robot.py` gives `robot0_eef_pos` from `eef_site_id` but `robot0_eef_quat` from `robot_model.eef_name` body orientation. They are not a single rigid pose whose translation and rotation can be applied to arbitrary pad offsets. This draft does not use them that way.

For a constant body-to-site rotation C, write S(t)=B(t)C. A requested world delta D gives the desired body orientation B*=D B(0), and corresponding site S*=D B(0)C. The relative global residuals agree exactly:

`S* S(t)^-1 = D B(0) C (B(t) C)^-1 = D B(0) B(t)^-1 = B* B(t)^-1`.

Thus a body-quaternion residual is valid for a **relative global rotation** about a site with a constant mounting offset. The installed OSC left-multiplies the axis-angle residual onto the current site orientation. For base frame A, transforming the world rotation vector by A.T yields the corresponding base-frame delta; this is already `target_action` behavior. Holding `robot0_eef_pos` separately controls the site's position. No assumption that C=identity is needed. This does not prove a generic robot with articulating or mismatched reference frames satisfies the constant-offset premise.

The inspected stock Panda XML has a fixed body path to grip_site, and the prior controller probe reports the expected OSC convention. The actual configured model's body/site mapping still needs a robot-only runtime snapshot. Before any R policy experiment, a finite isolated probe must record actual body name, site name, gripper class, both world orientations and C at every probe step, demonstrate C is constant (rotation geodesic difference <=1e-7 rad), and confirm controller reference site matches observed EEF site. If that gate fails, do not deploy R or infer pad geometry from this proof. Do not change the original getter or defaults to make the gate pass.
