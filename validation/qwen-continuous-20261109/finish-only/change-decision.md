# F: 必须显式结束的独立 API 工作流候选

记录于实施之前，依据本轮用户明确授予的 LIBERO 持续自动优化权限。第七轮 W2 的 task0 在成功读取三个启动输入后，只输出动作意图，没有工具调用。SDK 接受 str 为终答，Dashboard 会话等待新消息，直到600秒；四格均为有效超时失败，原记录不替换。

## 精确改动与适用范围

具体前后内容见 [四文件补丁](finish-only.patch)，基线 SHA 见 [清单](base-hashes.json)。仅新增默认 false 的 server-owned `api_require_finish`，本轮只在独立 LIBERO API 工作台启用；不得从任务请求覆盖。真机、UniVTAC、原主工作台和默认配置保持。

- `rpent/dashboard/workbench.py`：校验布尔开关，限制本入口为 LIBERO/API，启用值写入已冻结任务和 manifest。
- `rpent/cli/dashboard.py`：将已冻结任务中的开关传入 planner 构造。
- `rpent/planner/base.py`：新增默认 false 参数，非 API 后端拒绝启用，向 API 适配器传递。
- `rpent/planner/api_loop.py`：启用时只移除输出类型的 `str` 分支，保留原 finish ToolOutput 和所有普通工具；没有 finish 工具时明确拒绝启动。

不增加提示词、文本解析器、调度器、策略 agent、自动动作或额外请求预算。单独文字由现有 SDK 输出校验提示重试；文字伴随真实工具调用仍被允许。finish 原有接受/拒绝逻辑保持，官方环境判分不变。

## 假设与边界

可证伪假设：去除纯文字终答，能避免07 W2 task0的正常会话等待，并让剩余预算用于模型继续调用工具或显式结束。它不保证正确抓取、语义定位、物体搬运或成功率；SDK约束生效不能当任务提升。模型也可能迅速调用失败finish或继续感知而不行动，这些均照计结果。

W2已判定无成功率收益，不提升为最佳版本；保留它作为这一机制修正的父条件。下一轮F只在相同 R18+W2 材料上启用此开关，两个环境分别跑task0/4 seed0各一次，600秒/30请求/16384、Flash非思考、无代理。与07 W2历史两格比较时明确时间与环境分配混杂，不能据此声称最终收益。原C历史参考仍为1/2的小样本。

1. 同步前核对本地四文件与冻结R源哈希，只在新的远程隔离副本运行；保留live及之前所有候选/数据。
2. 离线 SDK 真实调用链配合 fake/model transport 检查：默认文本终答不变；启用后纯文本触发RetryPromptPart并继续；混合文本+工具照常执行；实际 OpenAI chat 请求tool_choice为required；finish接受/拒绝、环境先结束、取消和30请求/600秒上限逻辑不被绕过。没有新增外部模型请求。
3. 工作台配置布尔值、server-owned不可覆盖、缺finish、非API后端、冻结manifest和实际构造参数验证；原工具声明、系统/用户提示与经验材料不变。
4. 远程定向检查、全单元与本轮相关hooks，独立复核差异；通过后冻结源码交接，再准备08 runner。root READY之前不启动策略实验。
