# UniVTAC 开发工作台

使用原 RPent dashboard，另起服务以保留 LIBERO 的环境与当前会话。
`start-univtac-workbench.sh` 使用 RPent Python 运行 planner，通过独立的
`univtac-python` wrapper 启动 Isaac；不修改系统驱动或全局 Vulkan 配置。
服务器凭据引用放在 `native-univtac/workbench.json`，不提交到 Git。
Qwen Max 配置启用推理；兼容 API 显式发送 `enable_thinking=true`。
本地 effort 非 `none` 值只控制该开关，不代表服务端接受推理强度分档。
Qwen API 域名通过服务 `NO_PROXY` 直连，Codex 保留远程代理。

- UniVTAC：远程 `127.0.0.1:8093`，本机转发 `http://127.0.0.1:18093/`。
- LIBERO：原远程 `8092` / 本机 `18092` 保留。
- 控制台 `/console`，历史 `/runs`，工具库 `/tools`。

## 当前实验方式（2026-10-26）

开始页手动选择任务、seed、模型、工具与预算，不再显示或绑定试点实验编号。
启动脚本不传入 `--pilot-root` / `--pilot-cell`，已使用的历史编号不会阻止新实验。
Qwen 的工具选择、参数使用和任务效果验证全部在真实运行的 UniVTAC 仿真中完成；
不再把历史观测发送给 Qwen 作为替代交互的离线验收。
旧批次的离线请求入口已关闭，历史 ledger、制作结果及失败记录保留。
连接检查只确认服务可达，不计为机器人能力实验；本次页面修改没有发起模型请求。

每轮最多 60 次模型响应、300 个短控制命令；单次模型等待上限 300 秒，
planner 上限 3600 秒；Qwen 推理保持开启，API 总输出上限 10000 token。
Codex SDK 的模型等待区间包含传输和重试、排除 RPent 工具执行时间。

对照组使用相同环境版本、任务、seed、控制接口、基础感知与推理预算，
仅改变预先规定的工具条件。可以从历史实验复制配置，再手动开始。
每轮独立留档、冻结工具源码，失败也保留。相同 seed 不保证物理状态完全相同：
原独立恢复检查尚未通过，必须继续检查初始观测和场景记录，不能宣称已实现严格配对。
原 40 次总预算继续作为研究约束，已完成的 10 次仍计入；新运行从实验记录汇总，
不再依赖旧固定编号。旧协议的正式冻结资格没有因移除页面而变为通过。

控制台在观测/动作返回时刷新外部 RGB、腕部 RGB、双指触觉及参考图，
不是动作期间的连续视频直播。完整录像在结束时刷盘，可从历史页面播放。
每个 `move_eef` 目标通常只推进两个 120 Hz 物理步（16.7 ms），没有额外稳定等待；
模型思考和观测不推进物理。新增说明对所有条件一致，控制实现未变。
触觉显示图是原生 [0,255] 浮点 RGB 的显式 RGB8 副本，原数组仍独立保存。
历史数据的缺失字段或相机外参不会由新代码补造。

启动工作台本身不启动模拟器。开始页配置后进入控制台，确认任务命令再手动执行。
每次实际实验启动独立模拟器和模型会话；页面修改和 CPU 回归检查不会执行机器人动作。
